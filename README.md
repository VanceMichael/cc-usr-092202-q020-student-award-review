# 傑出學生評審證據室

管理傑出大專學生選舉的提名證據、外部驗真、評委回避、多階段評分、申訴凍結與結果發布。
本庫只含**虛構樣例資料**與不依賴第三方庫的讀取／校驗邏輯，不含任何帳號、密鑰或連接憑據。

## 業務事實

- 選舉同時考察**學業成績、領導才能、社會服務**，候選經歷分散在院校、社團與公益機構。
- 獲獎者來自不同大專院校和經歷領域。
- 青年發展計劃強調拓寬視野與參與社會建設。

## 協作角色

- 候選人與提名人
- 資料核驗人員（院校、社團、公益機構、公共創作典藏庫、選舉秘書處）
- 評委（初審、面談、終審各階段按回避分配）
- 申訴處理人員
- 結果發布與資料管理人員

## 工作流（由 `fixtures/context.json` 完整示範）

1. **材料收取與分軌驗真**：提名授權（秘書處）、成績證明（院校）、項目角色（社團）、
   服務時數（公益機構）、推薦意見（推薦人）、公開作品（公共典藏庫）六類材料分別收取、
   分別走對應軌道驗真，互不替代。
2. **版本留存**：補交（resubmit）、更正（correction）、撤回（withdrawal）一律新增版本，
   被替換的舊版保留為 `superseded`，撤回版保留為 `withdrawn` 僅供審計；只有現行
   `active` 版本在其所屬軌道獲得 `confirmed` 才能生成「確認事實」。
3. **利益申報與回避**：評委在首階段開始前申報利益，系統拒絕讓已申報評委給該候選人評分。
4. **多階段凍結評分**：匿名初審（S1，僅見卷宗編號）、面談（S2）、終審（S3）各自在階段
   開始前凍結評分標準（rubric 權重合計為 1），評分只能在階段窗口內錄入。匿名映射在初審
   凍結之後才啟封。各階段能看到的事實 = 對該階段可見、且在標準凍結時點之前已確認的事實。
5. **極端分差只觸發覆核**：任一維度評委分差達到閾值（樣例為 3.0）即生成覆核記錄，
   `elimination_effect` 恆為 `none`；候選人不會因此被淘汰或移出後續階段。
6. **申訴凍結**：終審後設申訴窗（樣例為 2026-05-11 至 2026-05-24），窗內只審查、
   `ranking_changed` 恆為 false；結果在凍結窗結束後才發布。
7. **獲獎理由**：只能引用本候選人、已確認、可公開的事實；敏感事實不得引用，未成年人公開
   姓名須有家長授權的 publication 範圍。未入選者不發布姓名與理由。
8. **未成年人與敏感經歷**：須有家長同意書及分階段授權範圍。樣例中 C005 的敏感服務經歷
   完整內容僅初審可見（F-0503），面談與終審只看到遮蔽摘要（F-0503R），且永不公開。
9. **保留與清理**：未入選者資料於發布後 6 個月刪除可識別內容（C004：2026-11-25），
   獲獎者封存 5 年，撤回版本保留 1 年審計軌跡。
10. **名次可重建**：`results.snapshot_id` 與 `reconstruction.id` 一致；從評分表、各階段
    凍結 rubric、有效評委清單、匿名映射啟封時間與合成權重，可重算每個最終名次。

## 樣例導覽

`fixtures/context.json` 為 2026 年度虛構選舉：5 名候選人（C001–C005，含 2 名未成年人）、
5 名評委（J1–J5）、30 份材料（36 個版本）、35 條外部驗證、20 條確認事實、57 張評分表、
2 條極端分差覆核（均維持原分、無淘汰效果）、2 宗申訴（駁回／撤回，均未改名次）。

最終名次（合成權重 S1 25% / S2 30% / S3 45%，階段分先按各自凍結權重平均並保留四位小數）：

| 名次 | 候選人 | 獎項 | 綜合分 |
| --- | --- | --- | --- |
| 1 | C002 李樂怡 | 冠軍 | 8.7813 |
| 2 | C001 陳以信 | 亞軍 | 8.7460 |
| 3 | C005 林子睿 | 季軍 | 8.7166 |
| 4 | C003 張家豪 | 優異獎 | 8.4688 |

材料軌跡中的代表性情節：C001 服務時數由 120 更正為 132；C003 角色由「總幹事」更正為

公開作品在初審凍結後才補交確認，故初審不得引用（F-0404 僅 S2/S3 可見）；C002 撤回已驗真的
攝影作品，舊版僅留審計軌跡。

## 目錄說明

- `contracts/domain.schema.json`：JSON Schema（2020-12），定義全部集合的字段、枚舉與必填項。
- `fixtures/context.json`：不含真實個人信息的公開樣例，可同時通過 Schema 與語義校驗。
- `src/records.py`：
  - `load_records(path)`：讀取並執行全部跨記錄不變量檢查；
  - `validate_domain(value)`：只校驗不讀文件；
  - `reconstruct_ranking(value)`：從評分表與凍結規則重建名次，返回每個名次當時的
    證據、rubric、有效評委與評分表清單。
- `tests/test_records.py`：正向流程與 29 個「只改一處」的變異反例（撤回版本成事實、
  COI 評委評分、凍結後事實進入初審、覆核變相淘汰、申訴窗改名次、快照 rubric／評委被篡改等）。

## 本地檢查

```bash
python -m unittest discover          # 38 項測試，零第三方依賴
```

可選安裝 `jsonschema` 後，測試會額外校驗 fixture 符合 `contracts/domain.schema.json`：

```bash
pip install jsonschema
python -m unittest discover
```
